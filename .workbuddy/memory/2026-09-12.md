## exhentai「下载过时种子」的归档状态改为 304

**需求**：下载页只有「Outdated Torrents」时，下载过时种子后写入 `hentai_archive.status` 由 `DownloadSuccess(200)`
改为 `NoNewerSeed(304)`（枚举注释：没有更新的种子即过时）。确认口径：两处下载过时种子的路径都改；
`handleLatestTorrent`（真 latest）保持 200；下载后按钮由 `hide()` 改为置灰。

**改动**
- `src/site/exhentai/exhentai-download-handler.ts`
  - 构造函数新增 `archives?: HentaiArchiveDto[]`（第 7 位：`titleHash` 之后、`silent` 之前）并加类字段
  - 新增 `resolveArchive(archives?)`：过滤 status ∈ {200,304}（排除 400），取 **max(date)** 作判重水位线
  - `handleNoArchive` / `handleExistingArchive` 写入值 200 → 304
  - `handleOutdatedTorrents` 判重改为缓存优先：`this.archives` 有值直接用；`undefined` 才回退
    `getHentaiArchivesMapByHash([hash])`，且**去掉了 status 过滤**（200 与 304 都算已处理）
  - `downloadAndArchive` 尾部 `tryHideDownloadButton()` → 置灰；抽出私有 `applyArchiveStyle()`，
    `markAsNoNewerSeed` 改为复用它（不再重复 try/catch）
- `src/site/exhentai/exhentai.ts`
  - 新增 `private archiveCache: Record<string, HentaiArchiveDto[]> | null`
  - `attachHandlersForInfos`：把既有批量结果 `archivesByHash` 存进缓存
  - 循环内既有 `const archives` 由 `archivesByHash[titleHash]` 改为 `(archivesByHash[titleHash] ?? [])`
    （查过但没记录 → `[]`，用于区分"数据未知"与"确实没有归档"），并直接注入 handler
  - `executeQueuedDownload` 同样注入缓存（`silent` 参数位置后移一位）

**关键设计（踩坑记录）**
1. 判重水位线用 `max(date)` 而非 `max(created_time)`：`markAsNoNewerSeed` 的写入守卫（过时种子不比归档新才写）
   保证 304 行 date ≤ 对应 200 行 date ⇒ 存在 200 行时与旧实现（只查 200）逐位等价 ⇒ 既有画廊零行为变更。
   若改用 created_time，一个 hash 同时有 200/304 两行时基准会漂移。
2. **放宽判重是必需项**，不是可选优化：改状态后若判重仍只查 200，下次进页面查不到刚写的 304
   → 走 `handleNoArchive` → 再下载 → 形成"每次进页面重复下载同一个过时种子"的死循环。
3. 304 行的 `date` 现在兼作判重水位线 ⇒ `downloadAndArchive` 的日期兜底（解析失败回退 `this.date`）
   **不能**改成跳过或 `dayjs(0)`：水位线归零会让每次进页面都判为"有更新"，直接回到重复下载。宁可偏高（少下载）。
4. `exhentai.ts` 的 for 循环体里**已经**有一个 `const archives`（供 UI 分支用）——新增注入变量会与之
   同作用域重名冲突，直接复用它更干净：把 `?? []` 加在源头即可（UI 分支对 `undefined`/`[]` 判断等价）。

**已知影响**
- 只下到过时种子的画廊今后长期停留 304：每次进列表页都置灰 + 自动复查一次下载页（并发 2 / 间隔 1.5s），
  不再"隐藏后安静"——这是 304 = 持续复查语义的必然结果
- 同页缓存快照不反写（同页不会二次处理同一 hash，无实际影响）
- `getDownloadedArchivesMap`（只查 200）在源码中无调用方，语义收窄为"已下载最新种子"
